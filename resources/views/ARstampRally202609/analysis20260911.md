# ARstampRally202610 旧iPhone「カメラ起動エラー」根本原因分析

- 作成日: 2026-09-11
- 対象: `ARstampRally202610`（不具合）／`ARstampRally202609@e0c369c`（正常参照）／`ARstampRally202605`（正常参照）
- 対象機器: iPhone 7（iOS 15）、iPhone SE 3rd（iOS 17.2）
- 結論: **DOM セレクタ誤り（`#ar-scene video` が常に `null`）**。AR.js が `<video>` を `<a-scene>` 配下ではなく `document.body` 直下に配置するため、カメラ監視が永遠にタイムアウトし、カメラが実動作していても「カメラを起動できません」を固定表示していた。

---

## 1. 症状

- iPhone 7（iOS 15）／SE 3rd（iOS 17.2）で、**マーカーは認識・3Dモデルも表示される（＝カメラは動作している）** にもかかわらず、
- エラー画面「カメラを起動できません」が**固定表示**され、
- 「低解像度で再試行」→ 再起動 → 再度同じ画面（無限ループ状）。

> ポイント: 「カメラが起動しない」のではなく、**起動しているのにその成功を検知できない**状態。

---

## 2. 根本原因（決定打）

`ARstampRally202610/head.blade.php` のカメラ監視・確保処理が、video 要素を次のセレクタで取得していた：

```js
document.querySelector('#ar-scene video')   // ← バグ
```

一方、AR.js 本体（`public/js/ar-tracking.min.js`）はカメラ video を **`document.body` 直下**に生成する：

```js
// ar-tracking.min.js（ARTracking クラス）
sceneWebcam = new I.Scene,
void 0 === g ? (
  B = document.createElement("video"),
  B.setAttribute("autoplay", !0),
  B.setAttribute("playsinline", !0),
  B.style.display = "none",
  document.body.appendChild(B)     // ★ document.body に追加される
) : B = document.querySelector(g),
```

`<a-scene id="ar-scene">`（`scene.blade.php:27`）自体は存在するが、**video はその子要素ではない**。
したがって `document.querySelector('#ar-scene video')` は **常に `null`** を返す。

結果として：

| 処理 | `#ar-scene video`（破損） | `video`（正常） |
|---|---|---|
| `monitorCameraStartup` の ready 判定 | `v` が常に null → 条件に到達せず → タイムアウト→「起動不可」を常時表示 | video を発見 → ready 判定 → エラー非表示 |
| `ensureCameraAccess`（再試行） | `v` が null → `play()` 不可 → getUserMedia 成功しても video へ接続不能 → 再起動手続きへ | video を発見 → play 成功 |

これにより、**カメラが正常に起動しても UI だけが「失敗」に固定**される。

---

## 3. 検証経緯

### 3-1. 正常版との差分（セレクタ違いが唯一の差異）
`202609@e0c369c`（正常）と `202610`（破損）の `head.blade.php` を diff した結果、
カメラ監視ロジックの**唯一の構造的差異**が以下のセレクタだった：

```diff
<                 const v = document.querySelector('video');        // 202609@e0c369c（正常）
---
>                 const v = document.querySelector('#ar-scene video'); // 202610（破損）
```

### 3-2. 正常系セレクタの一貫性確認
- `ARstampRally202605/head.blade.php`（動作実績あり）: **3 箇所すべて `querySelector('video')`**（行 40 / 64 / 78）。
- `ARstampRally202609@e0c369c`: **`querySelector('video')`**。
- 現行 `ARstampRally202609`（HEAD）: **`querySelector('#ar-scene video')`** ← 202610 と同様のバグ。

→ 正常系（202605、202609@e0c369c）は `video`、破損系（現行202609、202610）は `#ar-scene video` と、**破損とセレクタが完全に相関**。

### 3-3. AR.js 本体の video 配置確認
`public/js/ar-tracking.min.js` / `ar-engine.min.js` を解析し、カメラ video が
`document.body.appendChild(...)` されることを確認（上記 §2）。
202610 の blade テンプレートにハードコードされた `<video>` は存在しない（＝ページ内唯一の video が AR.js カメラ video）。
よって `document.querySelector('video')` は確実にカメラ video を取得する。

---

## 4. なぜ従来の修正（T15–T18 / FR-8–FR-11）が効かなかったか

従来の修正はすべて**正しい安全策**だったが、**同じ壊れたセレクタ `#ar-scene video` に依存**していた：

- **T15（監視継続/自動復帰）**: `setInterval` は継続するが、`const v = querySelector('#ar-scene video')` が常に null → ready 判定が永遠に未達 → エラー非表示にならない。
- **T16（二重 getUserMedia 防止）**: `if (v && v.srcObject)` の `v` が null → 条件が成立せず → 従来どおり getUserMedia 実行 → 再び null の video へ接続不能 → 再起動へ。
- **FR-9/FR-11（タイムアウト拡張 / arjs-video-loaded 連動）**: `arjs-video-loaded` イベントは発火するが、UI 側（monitor）が video を見つけられないため誤表示を消せない。

→ **セレクタが根本なので、上層のロジックをいくら強化しても無効**だった。

---

## 5. 修正内容

`ARstampRally202610/head.blade.php` の 3 箇所を `#ar-scene video` → `video` に復旧した
（202605 / 202609@e0c369c と同一の動作実績セレクタ）：

| 位置 | 関数 | 修正 |
|---|---|---|
| `monitorCameraStartup` の `setInterval` 内 | ready 判定 | `querySelector('video')` |
| `ensureCameraAccess` 冒頭 | 既確保判定 / play() | `querySelector('video')` |
| `getUserMedia` 成功ハンドラ内 | video 接続 | `querySelector('video')` |

既存の安全策（監視継続・二重getUserMedia防止・iOS 向け 15 秒タイムアウト・`arjs-video-loaded` 連動）は、
すべて**補完的かつ安全**なため**そのまま維持**した。

- 検証: `php -l` 通過。`#ar-scene video` のコード残存なし（コメント／design.md の記述のみ）。
- 202610 の blade テンプレートに他 video 要素なし（唯一の video は AR.js カメラ video）。

---

## 6. 影響範囲・要対応

- **`ARstampRally202609`（現行 HEAD）にも同様のバグ**（行 51 / 75 / 89 が `#ar-scene video`）。
  202609 も旧 iPhone で同症状になる可能性が高い。202610 と同様に 3 箇所を `video` に復旧することを推奨。
- 本修正は `ARstampRally202610` に適用済み。

---

## 7. 再発防止（推奨）

1. **AR.js の video 取得は常に `document.querySelector('video')`** を使うこと（`#ar-scene video` を使わない）。
   AR.js は `<a-scene>` 配下ではなく `document.body` に video を置くため。
2. 新規ライバル作成時は、**動作確認済みライバル（202605 / 202609@e0c369c）のカメラ監視を正として複製**する。
   「`<a-scene>` 配下」という誤った前提でのセレクタ絞り込み（`#ar-scene video` 等）を行わない。
3. 旧 iPhone（iOS 15 等）実機での**カメラ起動確認テストを必須項目**とする（本バグは実機 iOS でしか顕在化しなかった）。
4. `design.md` の記述（行 76「`#ar-scene video` をポーリング」）も、修正後と整合させること。
