## 3-3. 機能要件（オフライン収集 → 帰宅後の応募・Q-12 案A 確定）
> 2026-10-28 起案 → **同日 案A で確定**（利用者回答）。確定値: **収集 2026-11-01 00:00:00 〜 2026-11-15 23:59:59 / 応募期限 2026-11-16 23:59:59（JST）**。
> 論点: 会場（屋内イベント会場等）では通信が不安定でオフラインになるが、利用者は**帰宅後の自宅 Wi-Fi で応募したい**。
> 現状の設計（FR-29 / FR-35 の `start` / `end` を収集・集計・応募のすべてに共用し、`scanned_at` をサーバー `now()` で記録）では、
> **イベント当日にオフラインで収集したスタンプが、再送した日（例 12/01）に記録され、収集期間外として 0 種扱い → 応募できない**。
> 202610 では `js-init.blade.php` の起動時 `flushScanQueue()`（未送信キューの自動再送）が既に動作しているため、
> **技術的には帰宅後の自動送信は成立している**。成立しないのは「送信日時が記録日時になる」ことと「応募期限が収集期間と同一」ことの 2 点である。

| # | 要件 |
|---|---|
| FR-49 | **帰宅後応募の保証**: オフライン中に収集したスタンプは `ar-scan-queue-202611` に保持し、同一端末・同一ブラウザの次回ロード（オンライン復帰）時に自動再送する。再送が**応募期限までに完了していれば**、収集種数は再送済みのスタンプをすべて含めて算出され、抽選応募できる（会場での通信可否に応募可否を依存させない） |
| FR-50 | **収集期間と応募期限の分離（案A・確定）**: `config/ar202611.php` に `collect_start` / `collect_end`（収集・集計・ガラポン・倍率の種数算出に使用）と `apply_deadline`（`apply-voucher` が受理する最終日時）を**別キー**として持つ。`collect_end` < `apply_deadline`。**確定値（利用者回答・2026-10-28）: 収集 `2026-11-01 00:00:00` 〜 `2026-11-15 23:59:59` / 応募期限 `2026-11-16 23:59:59`（JST）** |
| FR-51 | **記録日時は収集日を保持する（案A）**: `record-scan` の `scanned_at` は、クライアントが送る `scannedAt` が **① `collect_start`〜`collect_end` の内 ② サーバー現在時刻より 24 時間以内の未来**という条件を満たす場合に限りそれを採用し、条件外（欠損・不正・期間外・大きく未来）の場合はサーバー `now()` へフォールバックする。これにより日別統計・動物別統計が**実際の収集日**で集計され、帰宅後の再送が 12 月へずれない。`applied_at`（応募日時）は常にサーバー `now()` のまま |
| FR-52 | **応募ボタンはサーバー算出種数でのみ表示**: スタンプ帳内の抽選応募ボタンは `check-status` が返す `stampCount`（= サーバー記録済み）が `voucher_threshold` 以上の場合のみ表示する。クライアント LocalStorage の収集数や**未送信キュー件数だけでは表示しない**。未送信キューが 1 件以上ある場合は応募ボタンを抑制し「未送信のスタンプ N 件を自動送信します」バナーを表示する（送信完了後に `check-status` を再実行して反映） |
| FR-53 | **スタンプ記録は端末内である旨の明示**: スタンプ収集状態は端末の LocalStorage / IndexedDB とサーバーの `marker_scans`（fingerprint 紐付け）に依存する。別ブラウザ・別端末・プライベートモード・ブラウザデータ削除では**引継ぎできない**ことを参加ページと README に明記する（案A/B/C 共通の必須要件） |

### Q-12 三案比較（2026-10-28 起案 → **案A で確定**・決定根拠として残置）

> 前提となる事実（202610 の実測）:
> - オフライン収集は成立している（SW cache-first + `ar-scan-queue-*`）。**ページを再度開けば未送信キューは自動で再送される**（`js-init.blade.php` の起動時 `flushScanQueue()`）。
> - ただし 202610 の `recordScan()` は `scanned_at` を**サーバー `now()`** で記録する（クライアントの `scannedAt` は validate のみに使用）。
> - 202610 の `stampCountFor()` は `whereBetween('scanned_at', $range)` で期間内のみ数える。202611 設計（FR-29 / FR-35）も同じ。
> - 結果: **11/23 にオフラインで 10 種集め、12/01 に帰宅して再送 → 12/01 記録 → 11 月期間外 → 0 種 → 応募不可**（現状設計の欠陥）。

| 観点 | **案A: 収集期間と応募期限を分離**（推奨） | 案B: 期間は 1 組・`scannedAt` のみ採用 | 案C: 開催 2 日間に期間を統一 |
|---|---|---|---|
| config キー | `collect_start` / `collect_end` / `apply_deadline`（3 個） | `start` / `end`（1 組） | `start` / `end`（1 組・例 11/23 00:00 〜 11/24 23:59） |
| `scanned_at` の源 | **クライアント `scannedAt` を条件付き採用**（収集期間内 かつ サーバー現在 +24h 以内）。条件外は `now()` | クライアント `scannedAt` を採用（上限ガードなし） | サーバー `now()`（変更なし） |
| 帰宅後（例 12/01）に応募できるか | **○ 可能**（`apply_deadline` まで。例 12/07 23:59:59） | **△ 収集期間内に再送できた場合のみ**（11/30 23:59 までに自宅 Wi-Fi でページを開く必要） | **△ 開催 2 日以内に再送できた場合のみ** |
| 日別・動物別統計 | **◎ 実際の収集日に計上**（11/23 収集 → 11/23 に計上） | ◎ 実際の収集日に計上 | **△ 再送日に計上**（11/25 再送は期間外で集計ゼロ） |
| 管理画面・CSV の整合 | ○ 収集実績は収集期間、応募実績は `applied_at`（12 月）で**別枠表示**（ダッシュボードに注記が必要） | ○ 同一期間で完結 | ○ 期間が短く明快 |
| 改ざん耐性 | ○ 収集期間外・大幅未来の `scannedAt` は `now()` へフォールバック。日付偽装で「過去の日」へ遡って追加することはできない | **△ 期間上限がない**ため未来日付の混入余地。重複判定（`whereDate`）も client 日付に依存 | ◎ サーバー時刻のみのため最も強い |
| 実装コスト | 中（config 3 キー／`stampCountFor()` の期間引数／`recordScan` のガード約 10 行／`apply_deadline` 判定／未送信バナー UI） | 小〜中（`recordScan` の 1 行変更＋ガード） | **最小**（config の値だけ。コード変更不要） |
| 利用者体験 | **◎ 会場がオフラインでも、帰宅後に自動送信されて応募できる**（FR-49） | △ 期間終了後の再送は 0 種扱いで応募不可 → クレーム要因 | × オフライン会場では応募困難（「その場で通信必須」） |
| 運営の周知事項 | 「応募期限は収集終了後 N 日」「スタンプは端末内の記録（別端末・別ブラウザに引継ぎ不可）」 | 「再送は収集期間内に」 | 「その場で通信できることが応募条件」 |
| 202610 からの差分 | 小（`recordScan` の `scanned_at` と `checkStatus` の期間のみ。SW・キュー・UI は同一） | 小 | なし |
| 残るリスク | client 時計のずれで当日分が前日扱いになりうる（±数時間）。`apply_deadline` 経過後の再送は 0 種扱い（422 `deadline_passed` で明示） | 期間経過後の再送が応募不可 | 帰宅後応募の要望に応えられない |
| **結論** | **採用（2026-10-28 利用者回答）**（帰宅後応募を保証し、統計も実態に沿う） | 不採用 | 不採用 |

**案A の確定値**（2026-10-28 利用者回答）:
1. `collect_start` = `2026-11-01 00:00:00` / `collect_end` = `2026-11-15 23:59:59`（JST）
